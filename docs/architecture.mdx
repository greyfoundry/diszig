title: 'Architecture'

The intended SDK has a thin public client facade and independently usable lower-level modules. Protocol types are shared, REST handles request scheduling and rate limits, and Gateway handles session recovery and event delivery. Builders and interaction helpers should work without requiring a full Gateway client where appropriate.

The intended repository is a Zig monorepo. A future root build will coordinate real packages; new modules are introduced when their functionality exists. The documentation site is a separate toolchain, not a runtime dependency.

The planned SDK layout is:

```text
build.zig / build.zig.zon  Root build and consumer package
src/root.zig              Public entrypoint
packages/protocol/        Shared wire types, IDs, permissions and routes
packages/rest/            HTTP transport, authentication and request scheduling
packages/gateway/         Sessions, recovery and event delivery
packages/builders/        Validated message and interaction payloads
packages/interactions/    Response lifecycle and signed HTTP delivery
packages/client/          Client facade, managers and cache policy
packages/sharding/        Native shards and local worker supervision
packages/voice/           Optional voice capability report; no transport,
                          codec or native dependency is linked
examples/                 Compiled consumer examples
tests/                    Cross-package fixtures and failure tests
benchmarks/               Reproducible measurements
```

These paths describe responsibilities, not existing packages. The protocol skeleton exists: `snowflake.zig` provides strict decimal IDs and timestamps, `timestamp.zig` parses and formats ISO8601, `cdn.zig` validates CDN image identity, `permissions.zig` implements documented overwrite ordering, `presence.zig` distinguishes absent/null/value, `errors.zig` provides bounded redacted context and `json.zig` provides tolerant-enum, one-of, size and depth bounds. `packages/protocol/models/shared.zig` begins the reviewed model batches with shared gateway/error/GitHub/automod/enum/permissions wire contracts; `packages/protocol/models/users.zig` adds the users batch 1 (account response, bot account patch, connected-account enums, profile metadata, widget and automation support types) with strict outbound validation and tolerant inbound enums; `packages/protocol/models/guilds.zig` adds the guilds batch 1 (guild/audit/scheduled-event/integration enums, ban and incident requests, prune/role-color/connection responses) with the same validation rules; `packages/protocol/models/applications.zig` adds the applications batch 1 (webhook status, explicit-content and application-type enums, OAuth2 key and scope wire mapping); `packages/protocol/models/channels.zig` adds the channels batch 1 (channel/overwrite/forum/thread enums); `packages/protocol/models/commands.zig` adds the commands batch 1 (command/handler/option/permission enums and number/string choice requests/responses); `packages/protocol/models/components.zig` adds the components batch 1 (button/component/separator/text-input/select enums and option/media requests); `packages/protocol/models/interactions.zig` adds the interactions batch 1 (callback/context/type enums and activity callback response); `packages/protocol/models/messages.zig` adds the messages batch 1 (message/reference/poll/reaction/mention enums, rich embed parts and embed/reaction responses); `packages/protocol/models/monetization.zig` adds the monetization batch 1 (entitlement owner/type/status, premium, SKU ineligibility and subscription status enums); `packages/protocol/models/resources.zig` adds the resources batch 1 (group DM invite request, invite target/type, scheduled-event user counts and sticker format/type); `packages/protocol/models/voice_control.zig` adds the voice-control batch 1 (empty stage/voice entity metadata markers, stage privacy levels and voice region response); `packages/protocol/models/social.zig` adds the social batch 1 (identity-provider auth types, OpenID Connect user info and provisional token response); `packages/rest/errors.zig` maps HTTP status and nested Discord validation errors without a global last-error, `packages/rest/client.zig` provides a standalone bounded REST transport with credential separation and same-origin redirects, `routes.zig`/`request.zig` provide normalized limiter identities and percent-encoded targets, and `limiter.zig` provides learned buckets, global pauses and bounded admission. `retry.zig` separates safe retries from ambiguous non-idempotent writes with finite attempt and deadline budgets. `multipart.zig` streams uploads, `cdn.zig` builds standard non-signed image URLs, `pagination.zig` provides bounded cursors and `audit.zig` encodes audit reasons; `oauth2.zig` builds the documented authorization URL, authorization-code/refresh/client-credential/revocation form bodies and Basic credentials, enforces S256 PKCE and callback state/issuer checks, parses token responses with secret redaction and performs no network I/O. `packages/gateway/transport.zig` opens one WebSocket, reassembles frames, answers pings, surfaces close frames and returns bounded payloads; `compression.zig` decodes Discord's shared `zlib-stream` context with a hard expansion bound; `heartbeat.zig`/`session.zig` parse Hello and drive jittered heartbeats, server heartbeat requests and missing-ACK zombie detection on a background deadline thread; `recovery.zig` builds Identify/Resume payloads, captures Ready state, classifies documented closes and holds separate identify/resume budgets and bounded backoff; `dispatch.zig` and `events/root.zig` provide a fixed-capacity per-shard FIFO with owned copies, typed READY/RESUMED, raw fallback and explicit overload; `protocol/events/channels.zig` and `gateway/events/channels.zig` type the first channel event batch with absent-versus-null updates and unknown-enum retention; `protocol/events/commands.zig` types APPLICATION_COMMAND_PERMISSIONS_UPDATE with a 100-entry bound; `protocol/events/guilds.zig` and `gateway/events/guilds.zig` type the first guild batch with a batch-1 guild subset and raw audit-log changes; `protocol/events/integrations.zig` and `gateway/events/integrations.zig` type the integration batch with a shared minimal user model; `protocol/events/interactions.zig` and `gateway/events/interactions.zig` type the INTERACTION_CREATE envelope with raw action data and a callback-scoped token; `protocol/events/invites.zig` and `gateway/events/invites.zig` type the invite batch; `protocol/events/members.zig` and `gateway/events/members.zig` type the member batch with a shared member model; `protocol/events/messages.zig` and `gateway/events/messages.zig` type the message batch with a shared create/update model and raw action-specific structures; `packages/builders/message.zig` and `embed.zig` validate and serialize message, embed, mention and attachment payloads; `packages/protocol/intents.zig` validates intent bits and privileged status, while `send.zig` builds every documented send payload and enforces the 120-events-per-60-seconds connection budget. The pinned client framing is vendored under `third_party/websocket/` with its provenance and local modifications recorded beside it. REST endpoints, automatic Gateway reconnect orchestration, typed event payloads beyond READY/RESUMED and sharding, the client facade, builders and interactions are not implemented yet. The root package and an external consumer are proven before expanding the tree.

## Serialization policy

Inbound responses are decoded tolerantly: unknown fields are ignored when the caller opts in, unknown enum values are retained through `InboundEnum` and can be recovered or reported, and a missing field, an explicit null and a value are distinct through `Presence`. Outbound requests are strict: they use concrete types and must not silently drop or invent fields. A one-of object must contain exactly one branch, checked before the branch is interpreted. Input byte length and nesting depth are bounded before parsing, and allocator failure unwinds the parse arena.

Public types are written and reviewed manually first. Generation is considered only after repeated measured need, with deterministic local inputs, reviewed overrides and no external reference fetching. A self-recursive model is handled with an explicit depth/size bound rather than recursive allocation.

Protocol types sit at the bottom of the dependency graph. REST, Gateway and builders consume them; interactions and the client compose lower-level modules. Sharding shares Gateway contracts across native and hybrid modes. Optional voice must not become a dependency of a basic REST consumer. Package names and public signatures remain subject to compiler-tested design.

Memory ownership, cancellation, error handling and resource bounds are part of the public contract. We will publish precise signatures and examples once the compiler-tested implementation exists.
