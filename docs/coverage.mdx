Coverage is tracked as evidence, not as a percentage. The manifest at
`coverage/coverage.json` records each implemented surface and is validated by
`python tools/check_coverage.py`. Internal planning inventories are not public
proof.

## Axes

Each surface tracks these independently:

- **Typed**: a real public type or function exists.
- **Raw**: a documented raw request/event path exists. Raw support is not typed
  parity.
- **Tested**: a test file exists and contains an executable test block.
- **Documented**: a public documentation page or contract exists.
- **Live verified**: an authorized test against Discord succeeded. This requires
  a date, authorization reference, exact artifact and result.

A surface can be typed but not documented, or documented but not live verified.
Those states are reported separately and never merged into a single "done" flag.

## Current status

Implemented and tested surfaces:

- Snowflake parsing, JSON string round-tripping and timestamp helpers.
- ISO8601 timestamp parsing and formatting.
- CDN image hash, format and size identity rules.
- Permission flags and documented overwrite, thread, timeout and hierarchy helpers.
- Caller-owned bounded error context with credential redaction.
- Structured HTTP status and nested Discord validation error paths.
- A standalone REST transport with bot/bearer separation and same-origin redirects.
- Normalized route identities and percent-encoded path/query construction.
- Learned bucket, global-limit and bounded-admission scheduling.
- Finite retry policy with explicit ambiguous non-idempotent writes.
- Streaming multipart uploads and standard non-signed CDN URL construction.
- Bounded cursor pagination and audit-reason encoding.
- Documented OAuth2 authorization, token, refresh, client-credentials and
  revocation request builders, with callback state/issuer checks and redacted
  secrets. No HTTP exchange or token storage.
- Gateway transport, bounded `zlib-stream` decompression, heartbeat liveness,
  Identify/Resume payloads, close classification, bounded recovery policy and a
  fixed-capacity dispatch queue.
- All documented Gateway send builders and intents, including the
  120-events-per-60-seconds connection budget.
- Typed channel, command-permission, guild, integration, interaction-envelope,
  invite, member and message event batches; unknown fields and enums are retained.
- Message and embed builders with documented validation.
- Shared protocol model batches: users, guilds, applications, channels, commands,
  components, interactions, messages, monetization, resources, voice control and
  social.

No REST endpoint wrapper, automatic Gateway reconnect orchestration, sharding
mode, client facade or voice capability is implemented or live verified.
Dispositions for the remaining documented product surfaces, including external
and deprecated SDKs, are in [Product scope](/scope). Planned and gated surfaces
remain in the internal inventory with a source and rationale; they are not
counted as shipped.

## Gated and external scopes

A surface may be marked `gated`, `external` or `deprecated` with a source and
reason. Gated product capabilities (for example approved-app RPC, monetization
or provisional accounts) remain visible and are not silently removed. External
client SDK boundaries are documented rather than emulated. The item-level
dispositions are in [Product scope](/scope).

## Fixtures

Synthetic fixtures live under `tests/fixtures/` and follow the rules in its
README. They must not contain credentials or private user data. Live tests are
separate and require explicit authorization.

## Commands

```bash
python tools/check_coverage.py
python tools/check_coverage.py --self-test
python tools/check_api_drift.py --self-test
zig build check
```

The checker rejects an implemented surface with no symbol, test or documentation
evidence, a live-verified surface with no dated evidence, and fixture files that
look like credentials.

## Source drift

`python tools/check_api_drift.py --baseline OLD.json --current NEW.json` compares
operation and model hashes without fetching or rewriting a pin. Removed, added
or changed operations/models are printed for manual review. Drift is a review
trigger, not an automatic upgrade, issue or release.

The reviewed standard and preview schemas are separate inputs. Comparing them
must report the known model differences rather than pretending the files are
interchangeable.
