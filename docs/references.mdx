## Official Discord documentation

The primary protocol reference is [discord/discord-api-docs](https://github.com/discord/discord-api-docs), Discord's official developer documentation repository. The rendered documentation is available at [Discord for Developers](https://docs.discord.com/developers/intro).

The initial research baseline is pinned to commit [`5a61ef8ebaf5e5702d3dc80e052d57001229ab1b`](https://github.com/discord/discord-api-docs/tree/5a61ef8ebaf5e5702d3dc80e052d57001229ab1b), acquired on 2026-11-24. Use immutable file links under this revision when recording a design decision. Review later upstream changes explicitly; a pinned reference does not freeze Discord's live API or prove that Diszig implements it.

Official protocol documentation takes priority over conventions in other SDKs. OpenAPI can help inventory REST operations and detect drift, but does not replace the documented Gateway, rate-limit, interaction, component or voice contracts.

## OpenAPI inventory baseline

The REST inventory uses [discord/discord-api-spec](https://github.com/discord/discord-api-spec) at commit [`654230017d4f5ee3e6a59a769ffc40cf61001e3f`](https://github.com/discord/discord-api-spec/tree/654230017d4f5ee3e6a59a769ffc40cf61001e3f). Two inputs are kept separate:

- Standard [`specs/openapi.json`](https://github.com/discord/discord-api-spec/blob/654230017d4f5ee3e6a59a769ffc40cf61001e3f/specs/openapi.json), SHA-256 `33be28e715283003426be4666c0b558a53ce2e9a54f13217666304a2865048ba`
- Preview [`specs/openapi_preview.json`](https://github.com/discord/discord-api-spec/blob/654230017d4f5ee3e6a59a769ffc40cf61001e3f/specs/openapi_preview.json), SHA-256 `ef1e865cacb7d0e5690bde8a7ac101e57396acd12942e8be503c44488e138495`

At this pin both inputs define 250 operations and 542 model names, but five models differ. Equal counts do not imply identical semantics. The schema repository describes its input as preview-quality; presence in the schema is an inventory fact, not proof of a permitted, stable or implemented API. The docs pin and schema pin are independent baselines and must not be treated as one synchronized snapshot.
