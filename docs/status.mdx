---
title: 'Project status'
---

The project is in early implementation. Governance, agent workflows, a documentation site, a repository metadata checker, a native Zig build graph and a protocol module are present. The protocol module provides strict Snowflake JSON/string parsing and timestamp extraction, ISO8601 timestamp parsing/formatting, CDN image identity validation, permission flags with documented overwrite/thread/timeout ordering, bounded and redacted error context, structured HTTP/Discord validation errors, a standalone bounded REST transport with route identities, encoding a learned-bucket limiter, bounded retry/ambiguity policy, streaming multipart uploads, standard CDN URL helpers, bounded pagination and audit-reason encoding, tolerant inbound JSON with presence, size and depth bounds, and the first two reviewed shared model batches. Unit tests pass in Debug and ReleaseSafe on Windows x86-64.

REST v10 is the default and REST v9 can be selected explicitly at the transport level; endpoint-level v9 coverage is not claimed. A Gateway transport boundary exists: WebSocket framing, ping/pong, close handling, bounded zlib-stream decompression and explicit URL parsing. Gateway session control covers Hello parsing, jittered heartbeat scheduling, server-requested heartbeats and missing-ACK zombie detection on a background heartbeat thread. Identify/Resume payloads, Ready-state capture, documented close-code classification, separate identify/resume budgets and bounded backoff are implemented. Dispatch has a fixed-capacity per-shard queue with typed READY/RESUMED, raw fallback, explicit `QueueFull` overload and no deduplication. The first typed channel event batch (CHANNEL_CREATE/UPDATE/DELETE/INFO/PINS_UPDATE) preserves absent-versus-null update semantics and unknown enum values. Intents are validated with an explicit privileged-intent acknowledgement, all documented send payloads have builders, and a 120-events-per-60-seconds send limiter treats the Gateway `RATE_LIMITED` dispatch separately from an HTTP 429. Automatic reconnect orchestration, typed event payloads beyond READY/RESUMED, sharding, the client facade, builders and voice are not implemented. A GitHub Actions workflow is committed with read-only permissions and pinned actions, and it has run on hosted Ubuntu and Windows runners; no required checks are configured remotely. The first functional client release is intended to include REST, Gateway recovery, native and local hybrid sharding, interactions, and legacy and Components V2 message building. Full typed API parity and optional encrypted voice follow in later milestones.

We will distinguish implemented, tested, documented and live-verified features. Experimental or permission-gated Discord APIs will be marked separately. There are no performance numbers or supported platform claims yet.
