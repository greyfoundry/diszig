---
title: 'Project status'
---

The project is in early implementation. Governance, agent workflows, a documentation site, a repository metadata checker, a native Zig build graph and a protocol module are present. The protocol module provides strict Snowflake JSON/string parsing and timestamp extraction, ISO8601 timestamp parsing/formatting, CDN image identity validation, permission flags with documented overwrite/thread/timeout ordering, bounded and redacted error context, structured HTTP/Discord validation errors, a standalone bounded REST transport with route identities, encoding a learned-bucket limiter, bounded retry/ambiguity policy, streaming multipart uploads, standard CDN URL helpers, bounded pagination and audit-reason encoding, and tolerant inbound JSON with presence, size and depth bounds. Unit tests pass in Debug and ReleaseSafe on Windows x86-64.

REST, Gateway, client, builders, sharding, voice and compiled examples are not implemented. A GitHub Actions workflow is committed with read-only permissions and pinned actions, but it has not run on a hosted runner and no required checks are configured remotely. The first functional client release is intended to include REST, Gateway recovery, native and local hybrid sharding, interactions, and legacy and Components V2 message building. Full typed API parity and optional encrypted voice follow in later milestones.

We will distinguish implemented, tested, documented and live-verified features. Experimental or permission-gated Discord APIs will be marked separately. There are no performance numbers or supported platform claims yet.
