title: 'Project status'
---

The project is in early implementation. Governance, agent workflows, a documentation site, a repository metadata checker, a native Zig build graph and a protocol module are present. The protocol module provides strict Snowflake JSON/string parsing and timestamp extraction, ISO8601 timestamp parsing/formatting, CDN image identity validation, permission flags with documented overwrite/thread/timeout ordering, bounded and redacted error context, structured HTTP/Discord validation errors, a standalone bounded REST transport with route identities, encoding a learned-bucket limiter, bounded retry/ambiguity policy, streaming multipart uploads, standard CDN URL helpers, bounded pagination and audit-reason encoding, tolerant inbound JSON with presence, size and depth bounds, and the first two reviewed shared model batches. Unit tests pass in Debug and ReleaseSafe on Windows x86-64.

REST v10 is the default and REST v9 can be selected explicitly at the transport level; endpoint-level v9 coverage is not claimed. A Gateway transport boundary exists: WebSocket framing, ping/pong, close handling, bounded zlib-stream decompression and explicit URL parsing. Gateway session control covers Hello parsing, jittered heartbeat scheduling, server-requested heartbeats and missing-ACK zombie detection on a background heartbeat thread. Identify/Resume payloads, Ready-state capture, documented close-code classification, separate identify/resume budgets and bounded backoff are implemented. Dispatch has a fixed-capacity per-shard queue with typed READY/RESUMED, raw fallback, explicit `QueueFull` overload and no deduplication. The first typed channel event batch (CHANNEL_CREATE/UPDATE/DELETE/INFO/PINS_UPDATE) preserves absent-versus-null update semantics and unknown enum values. APPLICATION_COMMAND_PERMISSIONS_UPDATE is typed with a 100-entry bound and unknown permission types retained. The first guild batch (GUILD_CREATE/UPDATE/DELETE, audit log entry create and ban add/remove) uses a batch-1 guild subset with `Presence` updates and raw audit-log changes. The integration batch (INTEGRATION_CREATE/UPDATE/DELETE) types the integration object, keeps unknown string types raw and omits the user field on create/update as documented. INTERACTION_CREATE types the interaction envelope; its `data` remains raw in this batch and the continuation token is treated as a callback-scoped secret. The invite batch (INVITE_CREATE/DELETE) types the documented event fields, keeps unknown target types raw and leaves the partial target application raw. The member batch types the shared member model and add/update/remove/chunk events, with chunk presences raw. The message batch types create/update/delete/bulk with a shared batch-1 message model, typed attachments and raw embeds/components/reactions/references/polls. The role batch types GUILD_ROLE_CREATE/UPDATE/DELETE with a documented role subset, presence-aware icon/emoji fields and null-as-true role tags. `packages/builders/` validates message/embed limits, explicit allowed mentions, edit content presence and attachment references before serialization. `protocol/models/users.zig` adds the first users model batch (account response, bot account patch, connected-account enums, profile metadata, widget and automation support types) with strict outbound validation and tolerant inbound enums, plus the batch-2 quarantine/timeout actions, target-users job, avatar decoration, nameplate and widget member. `protocol/models/guilds.zig` adds the guilds batch 1 (guild/audit/scheduled-event/integration enums, ban/incident requests and prune/role-color/connection responses) with the same rules, plus the batch-2 integration/onboarding/tier/team-role enums, lobby invite, role-color validation, empty unban request and bounded role-connection patch. `protocol/models/applications.zig` adds webhook/explicit-content/application-type enums and OAuth2 key/scope contracts, now with wire-mapped scope JSON and the batch-2 install-link parameters and key list. `protocol/models/channels.zig` adds the channel type, overwrite, forum layout and thread sort/archive/search enums. `protocol/models/commands.zig` adds command handler/type/option/permission enums and number/string choice requests and responses. `protocol/models/components.zig` adds button/component/separator/text-input/select enums and radio/checkbox/media requests. `protocol/models/interactions.zig` adds callback type, context and interaction type enums plus the activity callback response, now with the batch-2 interaction response, callback requests and SKU purchase eligibility data. `protocol/models/messages.zig` adds message/reference/poll/reaction/mention enums, rich embed parts and embed/reaction responses, plus the batch-2 video embed, searchable embed type and Slack webhook field. `protocol/models/monetization.zig` adds entitlement, premium, SKU-ineligibility and subscription-status enums. `protocol/models/resources.zig` adds invite target/type and sticker format/type enums, the group DM invite request and the scheduled-event user count response, plus the batch-2 settings emoji and standard sticker responses. `protocol/models/voice_control.zig` adds stage privacy levels, entity metadata markers and the voice region response. `protocol/models/social.zig` adds identity-provider auth types, the OpenID Connect user info response and the provisional token response. `rest/oauth2.zig` builds documented authorization URLs, authorization-code/refresh/client-credential/revocation form bodies and Basic credentials, enforces S256 PKCE plus callback state/issuer checks, parses token responses and redacts secrets without performing network I/O. Intents are validated with an explicit privileged-intent acknowledgement, all documented send payloads have builders, and a 120-events-per-60-seconds send limiter treats the Gateway `RATE_LIMITED` dispatch separately from an HTTP 429. Automatic reconnect orchestration, typed event payloads beyond READY/RESUMED, sharding, the client facade, builders and voice are not implemented. A GitHub Actions workflow is committed with read-only permissions and pinned actions, and it has run on hosted Ubuntu and Windows runners; no required checks are configured remotely. The first functional client release is intended to include REST, Gateway recovery, native and local hybrid sharding, interactions, and legacy and Components V2 message building. Full typed API parity follows in later milestones. Optional voice is unavailable: diszig.voice only reports why (DAVE is the only documented call mode for audio from 2026-03-01, and no native codec/DAVE dependency is pinned), linking nothing and returning rror.UnsupportedVoice. `docs/scope.mdx` records the disposition of every audited product surface, including external client SDKs, deprecated products and retained server endpoints.

We will distinguish implemented, tested, documented and live-verified features. Experimental or permission-gated Discord APIs will be marked separately. There are no performance numbers or supported platform claims yet.
