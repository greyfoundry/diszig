---
title: Voice (optional, in progress)
description: Current voice status, DAVE requirements and the libdave integration plan
---

Voice is **not implemented yet**. Discord voice itself is fully supported; what
Discord discontinued was the **legacy non-DAVE connection**. Ordinary calls now
require DAVE end-to-end encryption, with enforcement from 2026-03-02. Stage
channels are exempt from the E2EE requirement.

`diszig.voice` is currently an explicit capability report: `isAvailable()` is
false, `require()` returns `error.UnsupportedVoice`, and the default build links
no WebSocket, UDP, Opus or libdave code. This is a current implementation gap,
not a platform limitation.

## What exists today

- **Pinned official libdave**: v1.3.0 (`v1.3.0/cpp`), MIT, with Discord's own
  shared-library release assets for Windows x64, Linux x64/ARM64 and macOS
  x64/ARM64. Each asset is pinned by SHA-256 in `tools/fetch_libdave.py`.
- **C ABI bindings**: `packages/voice/dave.zig` binds a small, real subset of
  the C API (max protocol version, session create/destroy, group init, protocol
  version, marshalled MLS key package).
- **Optional ABI probe**: `zig build voice-probe -Dlibdave-dir=...` links the
  official library, creates a session, initializes it, obtains a key package,
  and exercises the encryptor/decryptor in passthrough mode. It is excluded from
  the default build and `zig build check`. A formed MLS group needs
  voice-server external-sender/proposal payloads.
- **Control layer**: `packages/voice/gateway.zig` covers the documented voice
  opcode inventory (including binary DAVE opcodes), close-code classification,
  AEAD negotiation (AES preferred, XChaCha required) with no plaintext fallback, main-Gateway state/server
  correlation in either order, endpoint normalization, Identify/Select Protocol/
  Heartbeat/Resume/Speaking/Media Sink Wants builders, JSON payload parsing and
  server binary framing. It opens no socket and sends no audio.
- **Transport primitives**: `packages/voice/udp.zig` builds and validates the
  74-byte IP-discovery packets with SSRC binding; `packages/voice/rtp.zig`
  builds/parses the Opus RTP header (including CSRC/extension length) and
  encrypts/decrypts `rtpsize` packets with AES-256-GCM or
  XChaCha20-Poly1305 using Zig's audited AEADs. Nonce, tag and trailer layout
  match Discord's documented modes; keys are zeroed on rotation and failed
  authentication exposes no plaintext. No socket is opened.
- **DAVE transitions**: `packages/voice/transitions.zig` is the opcode 21-31
  state machine (epoch preparation, proposals, commit/welcome, ready, execute,
  downgrade, immediate transition 0, explicit invalid-commit plus key-package
  reset), with JSON codecs for opcodes 21-24/31 and binary framing for 25-30.
  `packages/voice/dave.zig` binds the public libdave session transition calls and
  exposes a `Driver` that copies key package/commit-welcome/epoch-authenticator
  output into caller buffers, plus encryptor/decryptor handles with key-ratchet
  assignment. The probe exercises session creation, key packages and passthrough
  media frames. A formed MLS group, ratcheted media and live transitions require
  voice-server payloads and remain pending authorized live verification.
- On 2026-11-27 the Windows x64 probe ran against the verified v1.3.0 asset,
  reported protocol 1 and produced a non-empty MLS key package (392-393 bytes
  across runs). That proves ABI feasibility; it is not a voice connection and
  not a support claim.

```bash
python tools/fetch_libdave.py
zig build voice-probe -Dlibdave-dir=third_party/libdave/v1.3.0/windows-x64
```

## Why there is no partial voice path

- A UDP/RTP client without DAVE would be unusable for ordinary calls because
  legacy non-DAVE connections were discontinued.
- Voice still needs the voice gateway v8 handshake, heartbeat with `seq_ack`,
  buffered resume, UDP IP discovery, one select-protocol per session, AEAD RTP
  framing and a codec pipeline. DAVE handles MLS and the media encryption
  context through libdave.
- Shipping a stub or a silent no-op would be a false support claim, so the
  package stays explicitly unavailable until the transport is real.

## Implementation phases

1. **Dependency feasibility and ABI** (done): pinned official libdave release,
   SHA-256 verification, Zig C-ABI bindings, optional probe, licence inventory.
2. **Control and negotiation** (done, transport-agnostic): opcode inventory,
   close classification, AEAD selection, state/server correlation and control
   payload codecs in packages/voice/gateway.zig.
3. **Optional integration package**: make libdave and Opus opt-in through a
   build option, with a `voice` feature that defaults off; add the required
   NOTICE entries and a platform support matrix. Default consumers still link
   nothing voice-related.
4. **Voice gateway transport**: v8 handshake, Identify/Ready/Session Description,
   heartbeats with `seq_ack`, buffered resume, close classification and bounded
   reconnect. Stage channels can connect without the E2EE media path.
5. **Transport primitives** (done): discovery framing with SSRC binding, RTP
   header parsing with CSRC/extension length, and AES-GCM/XChaCha rtpsize
   encryption with key rotation. Remaining: the UDP socket, select-protocol
   once per session, RTCP, pacing and bounded jitter buffers.
6. **DAVE session lifecycle** (protocol state machine done): external sender,
   proposals, commit/welcome, epoch transitions, key ratchets and
   encryptor/decryptor handles through libdave. Live MLS group transitions need
   authorization and real voice-server payloads. MLS state is never
   reimplemented in Zig.
7. **Audio**: Opus encode/decode with explicit ownership, pacing, buffering and
   allocation-failure tests; receiving audio only where documented.
8. **Recovery and packaging**: connection recovery tests, per-target consumer
   builds, reproducible artifact fetching, shutdown/join guarantees and
   resource bounds.
9. **Verification**: deterministic protocol/encryption fixtures first; live
   voice checks only with explicit authorization and dated evidence. No
   operational voice claim before that.

## Current surface

```zig
const voice = diszig.voice;

if (voice.isAvailable()) {
    // never taken today
} else {
    _ = voice.require() catch |err| switch (err) {
        error.UnsupportedVoice => {}, // disable the feature
    };
}
```

`voice.reasons` records the DAVE requirement, the probe-only dependency state
and the missing transport. `voice.documented_gateway_version` is 8 and
`voice.encryption_modes` lists the two current AEAD modes. `voice.libdave_release`
is `v1.3.0/cpp`.
